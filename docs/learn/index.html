X3D Elucidation: the deep-learning base for an AI-accountable 3D format

On this page (8 sections)How to read a claim hereThe system in one pictureReading pathsThe chaptersWhat every chapter containsThe code bases this base was read againstRun it yourself, for freeGrow it

Thesis: X3D is the 3D format an AI can be held accountable to. Its rules are machine-readable, so software can say exactly what is wrong; a second renderer shows what is visible; a ledger travels with the file. This base teaches that machinery, measures it, and marks where it stops. L (the claim is argued across chapters 01 to 05; only the measured parts are C)

This is the learning base for people who already believe in X3D and want the framework in depth: the laws, the traps, the instruments, the numbers and the honest limits. It sits beside six AST teardowns of the code bases that produced the numbers (x3d-blender-io, x3d_mcp, x3d.loom, x3d.onto, x3d.demo, X_ITE 16.7.0); the teardowns say what the code is, these chapters say what it teaches.

How to read a claim here

mark meaning what stands behind it
C Confirmed measured, or read in the exact file; the instrument is named beside the number
L Likely read in a source we trust or reasoned from C facts; the source is named
S Suspected a guess or a design expectation; never a premise for a C

The instrument rule. A number without its validator, renderer version or rig is a rumour. Every number in the Numbers register of every chapter names its instrument, for example x3d_mcp fork b4efcd3, X_ITE 16.7.0 on Chromium 153 / SwiftShader, bpy 5.3.0. The register of all instruments is Appendix A; every number is in Appendix C. A result holds only at the pin it names: re-run it at a new pin and add a dated row, never overwrite the old one.

Run it yourself, for free

git clone https://github.com/hagopjay/x3d.docs && cd x3d.docs
pip install markdown-it-py mdit-py-plugins
python3 docs/tools-shared/check_learn.py --warn --summary   # lint: template, grades, ids, drills, leak sweep
python3 docs/tools-shared/build_learn.py                    # ledgers (Appendices A, C, D, E, F) + HTML
python3 -m http.server -d docs 8000                         # open http://localhost:8000/learn/

Everything uses free tools. No chapter requires a GPU, a paid API or an Unreal install; where a claim does (chapter 12), it says read, not run and gives the test that would promote it.

Grow it

This base is meant to be curated continuously. The loop is in AUTHORING section 6: observe, write the rule with the lowest grade the evidence allows, name the instrument, add a drill that would have caught it, rebuild, log it in the changelog. A later measurement that contradicts a C row demotes it and records both numbers.

Grades: C confirmed (measured, instrument named) · L likely · S suspected. Every number names its validator, renderer or rig. Rebuilt by docs/tools-shared/build_learn.py.

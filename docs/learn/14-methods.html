1. The map

   READ the rule --> PREDICT the result --> RUN the tool --> COMPARE --> GRADE the gap
        ^                                                                   |
        |                                                                   v
   PIN + DATE  <---- RECORD heuristic with falsifier <---- EXPLAIN why prediction missed
        |
        +--> re-run at a new pin: add a dated row, demote on contradiction
method what you do where it is practised failure it prevents
M1 predict-then-run write the expected output before running the drill every L2 drill reading answer keys as facts
M2 seed-a-failure take a valid scene, apply one failure mode, predict the diagnostic code 03, 02 trusting a gate that never saw a bad input
M3 two-renderer reading state a render claim as patch plus rig, then check it in a second renderer 06, 08 one renderer agreeing with itself
M4 grade ladder demote any number you cannot re-derive to L or S AUTHORING rumours promoted to facts
M5 pin-and-diff re-run a C row at a newer commit; record both A, F stale numbers
M6 minimal reproduction cut a failing scene to the smallest file that still fails 03 bugs reported without evidence
M7 teach-back restate a chapter as 3 heuristics each with a falsifier this chapter passive reading

Read next: 02 for the failure modes to seed; D for the rules to attack.

2. A four-week curriculum

week read drills (run, do not skim) checkpoint you can state
1 01, 03 all L2 drills of 01 and 03 which rung of the ladder catches a given fault, and which rung never will
2 06, 08, 10 one L3 per chapter a render claim with patch, rig and a second-renderer number
3 04, 05, 02 tool-call transcripts, SPARQL and SHACL drills a repair loop and what valid-but-wrong still escapes it
4 09, 11, 12, 13, 07 the not-run drills one new row in a Numbers register, with its instrument, sent as a PR

3. Cross-chapter patterns (the same lesson in different clothes)

pattern seen in one-line form
exact oracle before judge 01, 05 if a file can answer exactly, do not ask a model
valid is not visible, not placed, not stable 03, 05, 13 every grammar pass opens a second question
producer and reader that share a reading agree on the bug 07 pin raw stored values, not only producer-vs-reader agreement
a fallback must announce itself 02, 08 silent degradation reads as success
a number is true at a pin 03, A name the commit or do not quote it
structure gates do not judge looks 11 a valid glb can be empty
native hosts teach seams 09 n=1 engine: lessons, not rankings
status claims for unrun targets stay low 12 no install, no C

4. Self-assessment: score your pipeline

 tether score   unreliable   exact     valid != works   history must   someone answerable
 (one point     writer?      oracle?   (render check)   travel?        later?
  each)           [1]          [2]          [3]             [4]            [5]
 4-5 = loop + ledger     3 = ledger + gate     0-2 = a log table is enough

Give one point each (the tether score of 01): unreliable writer; exact oracle available; valid differs from works; history must travel with the artifact; someone answerable later. 4 to 5: full tether (loop plus ledger). 3: ledger plus gate. 2 or less: a log table is enough. Only X3D is measured in this base; any other family you score is your own S until you run it.

D-MET-4 Pin audit

  • Level: L2
  • Task: Pick three C rows from different chapters and find the repo and commit for each in Appendix F.
  • Verify: open F; each cited repo@sha must appear.
  • Answer: every cited pair is listed with its chapters; a row whose source has no pair is a defect to report.
  • Checked: not run.

D-MET-5 Teach-back

  • Level: L3
  • Task: Restate one chapter as three heuristics with falsifiers and a grade each; submit as a PR to that chapter.
  • Verify: check_learn.py passes and the new ids are unique.
  • Answer: none fixed; the check is a clean lint plus a drill that would have caught the rule.
  • Checked: not run.
